# 3D objects & models

Use 3D when **an object explains the product** (the brand metaphor, the physical thing, the data shape) and the page benefits from one memorable moment. Don't use it as generic decoration.

## Decide the source (in this order)
1. **Procedural in Three.js**: primitives, extrusions, and lathes built in code. It's crisp, tiny (0 KB of assets), exactly on-brand, and fully controllable. Best for simple, iconic objects (a keyring, a card, a coin, a device silhouette, stacked blocks, a dial).
2. **Open-licence models (glTF/GLB):** Poly Haven (CC0 models and HDRIs), Kenney (CC0), Quaternius (CC0), Smithsonian 3D (CC0 items), Sketchfab (check each model's licence and credit CC-BY). Compress with `gltf-transform optimize in.glb out.glb --compress draco --texture-compress webp` and keep it < 1.5 MB.
3. **Spline** (designer-made, embeddable): fine for prototypes. Ship the exported glTF rather than the heavy runtime when possible.
4. **Pre-rendered** (Blender → WebP/AVIF image sequence or a single still): when interaction isn't needed, this is the fastest and most reliable. Often the right answer on mobile.

## Quality recipe (procedural or glTF)
- **Lighting:** `scene.environment = pmrem.fromScene(new RoomEnvironment()).texture` for soft studio reflections with no external HDR file, plus one warm key `DirectionalLight` and a soft contact shadow (a `ShadowMaterial` plane or a blurred radial gradient under the object).
- **Materials:** `MeshPhysicalMaterial` for the hero only. Use metal `metalness 1, roughness 0.25–0.4` (brass `#D4A72C`, steel `#C9CFCB`), plastic `metalness 0, roughness 0.45, clearcoat 0.3`, and glass only if the story needs it (transmission is expensive). Take colours from the brand palette, never a rainbow.
- **Holes in extruded shapes:** build circles with exactly `Math.PI * 2` (`absarc(x, y, r, 0, Math.PI * 2, true)`). A rounded constant like `6.283` makes a clockwise arc a near-zero sliver, so the hole is never cut, and a ring "through" it passes through solid material. `inspect3d` catches this as a clearance FAIL. Ray-test it or look at the views if unsure.
- **Form:** rounded everything. Use `RoundedBoxGeometry`, `ExtrudeGeometry` with `bevelEnabled` (bevel ≈ 6–10% of thickness), and enough `curveSegments` (24+) that edges don't facet. Real proportions beat "cool" ones.
- **Camera:** 30–40° FOV, slightly above eye level, and the object filling ~60% of its box.
- **Colour management:** `renderer.outputColorSpace = SRGBColorSpace`, `toneMapping = ACESFilmicToneMapping`, and exposure around 1.0. Canvas textures (labels) get `colorSpace = SRGBColorSpace`.

## Assembly: the part models get wrong (and don't notice)
Models place parts where they *look* right from the hero camera. In 3D they end up floating, sitting in front of what they should thread through, turned sideways, or cutting through each other. The front view hides all of that. (Example: a keyring whose fobs sat in front of the ring. It passed a screenshot review and failed every geometric check.)

1. **Write the assembly spec before any geometry**, one line per relationship: `fob THREADS ring through hole H (axis ∥ wire)`, `lid RESTS ON box top`, `handle ATTACHES TO mug at A and B`, `screen INSET IN bezel`, `nothing floats`, `no part passes through another`.
2. **Build from the relationship, not from eyeballed positions.** Compute placement from the parent's geometry: a point on the wire's centreline, the tangent there for the hole axis, gravity projected into the plane the part can swing in, and a contact point on the surface. Put each part's pivot at its hole or contact point, so rotations (animation) keep it attached. Motion must be physical: a threaded part swings about the wire, and nothing slides off or through.
3. **Auto-fit the camera** to the assembled bounding box; never hand-tune numbers until it "looks right".
4. **Verify geometrically:** name parts and declare relationships (`userData.part`, `.threads`, `.attach`, `.centerline`, plus `poses` for animation extremes), expose `window.__inspect3d`, and run `node scripts/inspect3d.mjs page.html`. It checks threading (hole centre on the wire, hole axis ∥ wire), attachment gaps, and interpenetration (ray-cast inside tests) **in every pose**, and renders 6 views. Any FAIL blocks shipping.
5. **Cross-review (a second opinion, every time):** give a reviewer that didn't build the model *only* the spec and `views.jpg` (a sub-agent with no build context, or yourself after writing down what you expect each view to show), and ask per relationship: holds / broken / can't tell, with the proving view. Fix everything found, re-run 4, and review again until both the geometry and the reviewer pass. Two clean passes in a row, not one.
6. **Then choose the hero angle** from the views (the most legible one), not before. Note that the orbit views use their own camera, so also check the actual hero in `shoot.mjs`: a mis-aimed hero camera passes every assembly check.

Page contract (a few lines):
```js
ring.userData = { part: 'ring', centerline: pts.map(p => p.toArray()) };             // wire path, local
fob.userData  = { part: 'fob-a', threads: { on: 'ring', hole: [0,0,0], axis: [0,0,1], clearance: 0.2 } };
lid.userData  = { part: 'lid', attach: { to: 'box', at: [0,-0.5,0], tol: 0.02 } };
window.__inspect3d = { THREE, scene, camera, renderer, root, pause(){…}, poses: { rest(){…}, 'swing +'(){…}, 'swing −'(){…} } };
```

## Motion (≤ one behaviour, plus pointer)
An idle sway or slow turn (period 6–10s, amplitude ≤ 8°), a pointer tilt (≤ 6°, eased), or scroll-linked rotation. Pause when offscreen (`IntersectionObserver`) and when the tab is hidden. With **reduced motion**, render one still frame and stop the loop.

## Performance and robustness budget
- Load Three.js from `cdn.jsdelivr.net/npm/three@<pinned>/build/three.module.js` with an import map for `three/addons/`. Import it only when the hero canvas is near the viewport.
- Repaint synchronously in the resize handler (`setSize` clears the canvas; waiting for the next frame shows a blank box on resize and in full-page screenshots).
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, ≤ 50 draw calls, ≤ 100k triangles, and one shadow at most.
- **Complete at rest:** put a static fallback in the DOM first: `inspect3d.mjs --poster fallback.webp` renders the *verified* model's hero view (a hand-drawn SVG can drift from the model and show a wrong assembly). Swap to WebGL only after the first frame renders, so there's no blank box, and keep the fallback on WebGL failure.
- Label with `role="img"` and an `aria-label` describing the object. It's decoration plus meaning, never content-only.
- Verify rendering with `shoot.mjs` and assembly with `inspect3d.mjs` (see above). Headless Chromium renders WebGL via SwiftShader, so a blank canvas in the sheet is a real bug.

```html
<script type="importmap">{"imports":{"three":"https://cdn.jsdelivr.net/npm/three@0.180.0/build/three.module.js","three/addons/":"https://cdn.jsdelivr.net/npm/three@0.180.0/examples/jsm/"}}</script>
<script type="module">
import * as THREE from 'three';
import { RoomEnvironment } from 'three/addons/environments/RoomEnvironment.js';
const renderer = new THREE.WebGLRenderer({ canvas, antialias: true, alpha: true });
renderer.setPixelRatio(Math.min(devicePixelRatio, 2)); renderer.toneMapping = THREE.ACESFilmicToneMapping;
const scene = new THREE.Scene(); scene.environment = new THREE.PMREMGenerator(renderer).fromScene(new RoomEnvironment(), 0.04).texture;
// build rounded, brand-coloured geometry here; one idle motion; pause offscreen; reduced motion → render once
</script>
```

## 3D slop: reject
Glossy chrome or iridescent blobs, floating crystals and torus knots, a glowing "AI brain" or neural sphere, a particle galaxy, a rotating low-poly globe, isometric floating laptops, a 3D emoji or mascot nobody asked for, a gradient mesh "aurora", and objects that spin constantly and fast. The test: **could this object sit on any AI startup's homepage?** If yes, it's slop. Use the product's own object.
